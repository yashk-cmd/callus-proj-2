🛡️ VeritasAI

Statistical Admissions Essay Diagnostics

VeritasAI is a statistical admissions-essay analysis platform designed to surface measurable writing patterns such as lexical predictability, sentence-rhythm variation, perplexity, and formulaic phrasing.

Important: VeritasAI does not claim to prove whether an essay was written by a human or generated by AI. Its output is diagnostic evidence for review, not an authorship verdict.

✨ Overview

VeritasAI combines a FastAPI + Python analysis backend with a Next.js + React frontend to provide an interactive essay-analysis dashboard.

The system processes an essay at both the document and sentence level and presents:

📄 Document statistics

🔎 Sentence-level diagnostics

📊 Signal distribution

🧠 Perplexity-based measurements

📈 Burstiness / sentence-rhythm measurements

📝 Formulaic phrasing detection

🔤 Lexical predictability features

⚖️ Review priority

💡 Evidence-based explanations

📋 Methodology and limitations information

🎯 Why VeritasAI?

Traditional AI-detection systems often reduce a complex writing assessment to a single percentage.

VeritasAI takes a different approach:

Essay
  ↓
Text Processing
  ↓
Statistical Features
  ↓
Multiple Diagnostic Signals
  ↓
Sentence-Level Evidence
  ↓
Overall Review Priority
  ↓
Human Review

The goal is to make the underlying evidence more visible instead of presenting an unexplained binary decision.

⚠️ Ethical Position

VeritasAI should be treated as a diagnostic tool, not an automated authorship judge.

A statistical signal can occur in:

Human-written text

AI-assisted text

Heavily edited text

Formulaic academic writing

Short or highly predictable passages

Therefore:

A high or low signal does not establish authorship.

The application explicitly communicates this limitation in its analysis interface.

🔬 Analysis Pipeline

VeritasAI follows a multi-stage analysis process.

1. Text normalization

The essay is normalized while preserving meaningful sentence content and paragraph structure.

2. Sentence extraction

The essay is divided into sentence objects.

Each sentence contains information such as:

id
index
paragraph index
text
start/end positions
tokenized words

3. Feature extraction

Document-level and sentence-level statistical features are calculated.

4. Diagnostic signals

The current pipeline includes:

Perplexity
Burstiness
Formulaic phrasing
Lexical predictability

5. Evidence generation

Each signal can produce:

Category
Title
Metric value
Flag level
Description

6. Sentence scoring

Signals are aggregated into a sentence-level diagnostic score.

7. Document classification

The system calculates:

Review priority
Signal distribution
Analysis complexity
Summary message

8. Frontend visualization

The final result is displayed through the VeritasAI dashboard.

📊 Diagnostic Signals

🧠 Perplexity

Measures how predictable a sequence of tokens is under the configured language model.

Higher or lower perplexity should not automatically be interpreted as evidence of AI authorship.

📈 Burstiness

Examines variation in sentence length and sentence rhythm.

The system compares individual sentence lengths against the essay-level sentence distribution.

📝 Formulaic Phrasing

Looks for configured patterns or phrases that may contribute to a formulaic-writing signal.

A detected phrase is evidence of a pattern, not proof of machine generation.

🔤 Lexical Predictability

Uses vocabulary-level measurements such as:

Type-token ratio
Repetition
Lexical variety

These provide additional statistical context.

🛠️ Troubleshooting

ModuleNotFoundError: No module named 'torch'

You are probably using the wrong Python interpreter.

Check:

which python

It should point to:

.../backend/.venv/bin/python

Then:

python -c "import torch; print(torch.__version__)"

If necessary:

source .venv/bin/activate
python -m pip install -r requirements.txt

Port 8000 already in use

Check:

lsof -nP -iTCP:8000 -sTCP:LISTEN

Then terminate the actual PID:

kill -9 <PID>

Do not literally type:

kill -9 PID1 PID2

Replace <PID> with the number returned by lsof.

Frontend cannot reach backend

Confirm:

Backend → http://127.0.0.1:8000
Frontend → http://localhost:3000

Then test:

curl http://127.0.0.1:8000/health

If that works, check the frontend API configuration.

npm dependency problems

From frontend/:

rm -rf node_modules .next
npm install
npm run dev

On Windows PowerShell:

Remove-Item -Recurse -Force node_modules
Remove-Item -Recurse -Force .next
npm install
npm run dev
